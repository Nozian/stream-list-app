# Streaming Watchlist Organizer — Web版 MVP

元リポジトリ: https://github.com/Nozian/stream-list-app

公開版（本人限定）: https://swo-watchlist.nozian.chatgpt.site

他の端末では、同じChatGPTアカウントで上記URLを開いてください。追加・編集・評価・視聴済み・削除は自動同期されます。通信できない場合は端末内にも保存し、再接続時に新しい変更を統合します。JSONバックアップは手動の退避にも使えます。

サービスごとに分断された「観たい」を個人ライブラリにする、端末内保存のWeb版です。元のChrome拡張をルートに残し、`web/` に独立したブラウザアプリを追加しました。外部パッケージのインストールやAPIキーなしで動きます。

## 起動

リポジトリのルートで以下を実行し、Chromeなどで http://127.0.0.1:4173 を開きます。

```sh
python3 -m http.server 4173 --bind 127.0.0.1 --directory web
```

HTMLファイルの直接ダブルクリックではなく、上記のHTTP経由で利用してください。保存先はブラウザとURLごとに異なります。ポートやホストを変更した場合は、JSONバックアップで移行してください。ブラウザのサイトデータ削除で記録が消えるため、定期的にバックアップしてください。

## 今回使える機能

- Prime Video・Netflix・U-NEXTの作品を同じ画面で管理
- 手動追加・編集・削除、任意のサービス作品URL
- 映画・アニメ・ドキュメンタリー・シリーズ・未分類
- サービス・種類・視聴状態の同時絞り込み、作品名・ジャンル・メモ検索
- 追加順・タイトル順・評価順
- 視聴済み、3段階スター評価（元拡張と互換）、メモ
- 現在のサービス・分類・検索条件に合う未視聴作品から「今夜の一本」
- 表示中の作品をCSV出力、CSV・JSONの取り込み、JSONバックアップ
- 同じChatGPTアカウント間でのクラウド同期
- Web Share APIによるサイト・作品のSNS共有（未対応環境ではURLコピーまたはX共有）
- TMDb検索とJustWatch検索への外部リンク
- 狭い画面への対応、キーボードで使える登録ダイアログ

初期データは空です。配信状況を推測したサンプル作品は登録していません。手動のサービス指定は配信中であることの確認を意味しません。

## 拡張機能からの移行

1. このフォルダの更新済み拡張をChromeで読み込み・再読み込みします。
2. 拡張の一覧画面から「Web版へ移行（JSON）」を選びます。
3. Web版の「データを取り込む」でそのJSONを選択します。
4. 件数と更新の確認後に取り込みます。作品・ジャンル・視聴済み・評価・メモを引き継ぎます。

APIキーやキャッシュは書き出しません。同じID、同じサービスとURL、または同じサービスとタイトルの作品は取り込み内容で更新し、他の作品は残します。元の種類が不明な作品は「未分類」にします。CSVはWeb版・拡張機能が出力する日本語列に対応し、タイトルとサービスを必須列として読み込みます。

元のmanifestが存在しない `adapters/` 配下を参照していたため、実在するルートのサービス別スクリプトへの参照に修正しました。実サービスにログインした状態での拡張動作は未検証です。

## 構成

| ファイル | 役割 |
|---|---|
| web/index.html | ライブラリ・登録フォームの構造 |
| web/style.css | 配色・カード・画面幅への対応 |
| web/app.js | 画面操作・ブラウザ保存・インポート/エクスポート |
| web/model.js | データ検証・旧形式移行・検索・CSV変換 |
| web/model.test.js | 移行・検索・CSVなどの自動テスト |
| viewer.html / viewer.js | 元の拡張画面とJSON移行ボタン |

保存形式は `schema: swo-web`, `version: 1`, `items: [...]`。作品IDはUUID、外部リンクとは分離しています。旧拡張のURLキーの個人データを取り込み時に作品レコードへ統合します。種類とジャンルを分離し、サービスと作品URLも保持します。現段階ではサービス違いの同じ作品は別レコードです。

## 次段階の設計

1. **作品情報の補完**: サーバー側のTMDb検索窓口を用意し、ユーザーが候補を選んで作品ID・作品種別・ジャンル・画像を確定する。検索先頭候補の自動採用による誤分類を避ける。APIキーはサーバーに保持し、認証・レート制限・キャッシュ・クレジット表記を加える。
2. **本当の作品単位の統合**: `titles`（TMDb ID等で識別）、`availability`（サービス別URL）、`library_entries`（ユーザーの視聴状態・評価・メモ）に分割。同一作品の複数サービス表示と、映画/TVなどの区別を維持する。
3. **複数端末**: 認証とユーザー別データベースを追加。所有者チェック、変更バージョンによる競合検出、既存JSONの移行手順を設ける。現MVPのブラウザ保存をこの保存層へ置き換える。
4. **取得との連携**: サービスのページから取得する役割は拡張に残す。まずJSON移行を使用し、その後、認証された取り込みAPIと明示的な送信操作を用意する。削除済みの配信作品と個人記録の削除は分ける。

Web版からサービスのウォッチリストを自動取得する機能とTMDb APIによる自動分類は未実装です。TMDbの検索リンクはAPI連携とは異なります。同期は更新時刻が新しい内容を優先するため、複数端末で同じ作品を同時編集した場合は最後の更新が残ります。

## 検証

```sh
node --test web/model.test.js
```

7件合格: 旧拡張の視聴記録移行、バックアップ往復と重複更新、複合フィルター、不正データ/URLの拒否、CSVの改行・引用符・数式対策、CSV取り込み、同期競合と削除の統合。

Chrome実画面: 登録フォーム、作品・評価・メモの保存と再読込、視聴済み変更を確認。Codex内蔵ブラウザでは表示できるものの、検証時にダイアログ操作が反応しなかったため、当面Chromeでの利用を推奨します。実ユーザーデータでの移行・サービス側の取得・API実通信は未検証です。
